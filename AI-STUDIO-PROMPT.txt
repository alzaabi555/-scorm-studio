استورد مستودع SCORM Studio Web المرفق وحافظ على وظائفه بدل إعادة بنائه كنموذج شكلي.
المشروع تطبيق HTML/CSS/JavaScript ثابت دون خادم أو Gemini API؛ يجب أن يبقى قابلًا للنشر على GitHub Pages داخل مسار مستودع فرعي.
المطلوب: واجهة عربية RTL، إنشاء SCORM 1.2 ZIP، قراءة Store وDeflate مع فحص CRC، المحافظة على مسارات موارد الدرس، تشغيل افتراضي عبر CacheStorage وService Worker، محاكاة SCORM API، حفظ الاستئناف، تقارير HTML/JSON.
حافظ على index.html وapp.js وzip.js وstyle.css وsw.js وplayer.html وplayer.js وruntime.html وdemo.html. لا تضف API key ولا ترسل ملفات المستخدم إلى خادم أو نموذج ذكاء اصطناعي.
أبقِ كل الروابط نسبية وService Worker داخل نطاق التطبيق. لا تستبدل خدمة الموارد بـ blob URLs لأنها لا تحافظ على مسارات المشاريع العامة.
إذا كانت معاينتك تمنع Service Worker أو التخزين، اعرض رسالة دقيقة ولا تدّعِ أن المعاينة تعمل. لا تحذف المعاينة؛ حافظ عليها للنشر المستقل عبر HTTPS.
لا تستخدم بيانات وهمية للدرجة؛ يجب عرض قيم LMSSetValue الفعلية. حافظ على تمرير SCORMBridge من المشغّل إلى محتوى الدرس المغلف.
تجنب إضافة React أو خادم بلا ضرورة. إذا احتجت إطار عمل فاضمن نشر ملفات المشغل وsw.js في مسارات مستقرة واختبر build الناتج عند النشر بمسار فرعي.
المحتوى موثوق فقط؛ لا تدّعِ وجود sandbox أمني أو شهادة مطابقة. لا تضف SCORM 2004 ما لم تنفذه وتختبره فعليًا.
ابدأ بفهم الملفات الموجودة، ثم تحقق من إنشاء الحزمة واستيرادها والدرجة والاستئناف والتقارير قبل أي تغيير بصري.
