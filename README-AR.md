# SCORM Studio Web — نسخة GitHub Pages

## ماذا تحتوي؟
تطبيق ثابت HTML/CSS/JavaScript، لا يحتاج Python أو npm أو مفتاح Gemini API.
إنشاء SCORM 1.2، استيراد ZIP، معاينة تفاعلية، محاكاة API، استئناف محلي، تقارير HTML وJSON.

## النشر على GitHub Pages
1. أنشئ مستودعًا جديدًا، مثل scorm-studio. يفضل موقع بأصل مستقل لا تشاركه تطبيقات حساسة.
2. فك ZIP وارفع محتويات الحزمة مباشرة إلى جذر المستودع، وليس ZIP نفسه.
3. تأكد أن index.html وapp.js وzip.js وsw.js وplayer.html وplayer.js وruntime.html وdemo.html وstyle.css في الجذر نفسه.
4. Settings > Pages > Build and deployment > Source: Deploy from a branch.
5. اختر main ثم /(root)، ثم Save.
6. انتظر اكتمال النشر وافتح رابط الموقع الظاهر في Pages عبر HTTPS.
7. اضغط «تجربة درس تفاعلي»، وأجب عن السؤال، ثم اختبر إعادة التشغيل والاستئناف.

لا تنشر الحزمة المحلية السابقة التي تحتوي server.py بدل هذه الحزمة: هذه نسخة مستقلة مخصصة للمواقع الثابتة.

## Google AI Studio
Google AI Studio بيئة بناء وتطوير وليست مرادفًا لاستضافة GitHub Pages.
يمكن استيراد مستودع GitHub من Build عند توفر Import from GitHub، أو إدخال ملفات المصدر في المشروع وفق واجهة حسابك. راجع AI-STUDIO-PROMPT.txt.
اطلب الحفاظ على المشروع ثابتًا، وعلى المسارات النسبية وملف sw.js كما هو، دون إضافة Gemini أو مفتاح API.
إذا أنشأ AI Studio مشروع React/Vite، يجب تقديم sw.js وruntime.html وdemo.html وplayer.html وملفاتها في مسارات ثابتة صحيحة (مثل public مع تعديل روابط الواجهة حسب البنية)، وليس حذفها أو تحويلها لروابط blob.
قد تمنع بيئة المعاينة داخل إطار تسجيل Service Worker أو الوصول للتخزين. لم تُختبر النسخة داخل AI Studio نفسه. عند ظهور تحذير المعاينة، اختبر نسخة GitHub Pages النهائية أو نشرًا مستقلًا مناسبًا؛ لا تعتبر معاينة AI Studio اختبارًا نهائيًا للمشغل.
يدعم AI Studio نشر التطبيقات إلى Cloud Run وفق وثائقه؛ هذا مسار مختلف وقد يتطلب إعداد Google Cloud وتكاليف وفق الاستخدام.

## الاستخدام
- اختر مجلد المحتوى كاملًا لتضمين الصور وCSS وJavaScript والمسارات النسبية.
- حدّد الصفحات ورتبها. جميع الملفات المحددة تُضمّن؛ احذف الأسرار والملفات غير اللازمة مسبقًا.
- اختر نمط الإكمال واضغط إنشاء ومعاينة.
- راقب الدرجة والحالة والاستئناف، وجرّب أحجام العرض.
- دوّن الملاحظات وأنشئ تقرير التقييم ثم نزّل ZIP.
- لفتح حزمة جاهزة اختر ZIP يحتوي imsmanifest.xml في الجذر.

## الربط بالأنشطة
داخل صفحة درس تُغلّفها الأداة:
```js
parent.SCORMBridge.setScore(85);
parent.SCORMBridge.setStatus('passed'); // أو failed أو incomplete
parent.SCORMBridge.complete(); // إكمال دون إعلان نجاح
parent.SCORMBridge.saveState({question: 2});
const saved = parent.SCORMBridge.getState();
```
تُخزّن حالة النشاط ضمن cmi.suspend_data بحد 4096 حرفًا شاملًا بيانات المشغل. لا تُستنتج الدرجات من شكل الصفحة.

## المتطلبات والحدود
- متصفح Chrome أو Edge حديث موصى به؛ الاستيراد المضغوط يستخدم DecompressionStream deflate-raw. لا توجد مكتبات CDN.
- HTTPS وService Worker وCacheStorage لازمة للمعاينة مع المسارات الأصلية. لا تفتح index.html من القرص.
- إذا منعت البيئة Service Worker، يمكن إنشاء ZIP وتنزيله، لكن المعاينة الكاملة لن تعمل.
- لا يتم رفع الملفات إلى خادم لمعالجتها. الحزم في CacheStorage والمحاولات في LocalStorage لهذا الأصل والمتصفح. لا يوجد تزامن بين الأجهزة.
- التخزين يخضع لحصة المتصفح ويمكن حذفه أو إخلاؤه. لا تعتمد عليه كنسخة احتياطية؛ نزّل الحزم والتقارير.
- حد الحزمة 120 MB بعد فك الضغط و10000 ملف. ZIP64 والتشفير وطرق ضغط غير Store وDeflate غير مدعومة. ZIP الناتج Store دون ضغط لتجنب الاعتماديات.
- SCORM 1.2 فقط. xml:base وملفات التشغيل الخارجية والمسارات المطلقة غير مدعومة. عدة SCOs تُختبر منفردة دون قواعد تجميع LMS.
- لا يتحول PHP أو قواعد البيانات إلى محتوى مستقل. الموارد الخارجية تبقى بحاجة للشبكة وقد تمنعها سياسات المتصفح.
- محاكاة API تفحص بعض الحالات والأطوال والقيم؛ لا تطبق جميع قيود SCORM ولا توفر شهادة مطابقة. اختبر على المنصة الحقيقية.
- المعاينة تشغّل المحتوى في نفس أصل الموقع حتى يتمكن من الاتصال بـAPI. هذه ليست بيئة عزل للمحتوى العدائي. استخدم حزمًا موثوقة وموقعًا مخصصًا. مستودعات GitHub Pages للحساب نفسه قد تشترك في الأصل؛ المجلد الفرعي ليس عزلًا أمنيًا. استخدم نطاقًا مخصصًا أو حسابًا منفصلًا عند الحاجة للعزل.
- لا يوجد تسجيل دخول أو مكتبة سحابية أو نشر تلقائي إلى منصة تعلم. لا تحتاج الأداة أي مفتاح Gemini.
